# 砍掉之后剩下的东西：Engram、Jev 与一条反规模的 AGI 路径

> 把智能拆开，比把智能放大更难。放大只需要钱，拆开需要判断力。

*发布于 2026年9月29日*

---

过去几年，关于 AGI 的主流叙事可以压缩成一句话：把模型做得更大，把数据喂得更多，把算力堆得更猛。

这个叙事在 2026 年出现了明显裂痕。裂痕不是来自算力不够，而是来自回报不成比例——公开预训练数据接近枯竭，算力投入的边际收益持续下滑，而更贵的模型并没有带来等比例的可用智能。TypeSafe 创始人、InstructGPT 作者之一 Diogo Almeida 有句话说得挺直白：“我们手里握着瓶中的闪电，可它却没什么用。”

闪电在瓶子里，但拧不开盖子。这一年冒出的一组新工作，拧盖子的方式出奇一致——**不是往里加东西，是往外砍。**

![分层智能：编译期记忆、运行时判断、慢推理](/images/posts/engram-jev-llm/three-layer-stack.svg)
*图：三层分工——L0 条件记忆在编译期，L1/L2 判断和 L3 推理在运行时。*

---

## 一、Engram：最有价值的发现不在跑分上

DeepSeek 2026 年 1 月的论文（arXiv:2601.07372）提出了 conditional memory 这个新稀疏轴。做法是把经典 N-gram embedding 现代化：对 token 序列做 N-gram 哈希，O(1) 查表拿 embedding，过一个学习出来的 gate 注入 Transformer 层。和 MoE 并列，成为扩展模型容量的第二条腿。

论文把它推到 27B 参数，在严格 iso-parameter、iso-FLOPs 的 MoE 基线上全面胜出。但如果只看这个，就把重点看漏了。

看它的提升分布：

| 维度 | 提升 |
|---|---|
| 知识检索（MMLU / CMMLU） | +3.4 / +4.0 |
| 通用推理（BBH / ARC-Challenge） | +5.0 / +3.7 |
| 代码 / 数学（HumanEval / MATH） | +3.0 / +2.4 |
| 长上下文检索（Multi-Query NIAH） | 84.2 → 97.0 |

**一个查表模块，推理涨得比知识还多。这不符合直觉。**

论文的机制分析给了答案：Engram 把 backbone 的前几层从**静态模式重建**里解放出来，等于把网络的有效深度还给了复杂推理。同时，局部依赖交给 lookup 之后，注意力容量被释放给全局上下文——所以长上下文检索能从 84.2 跳到 97.0。

这件事的意义远超一个模块的得失。它说明了一件一直被忽略的事：

> 神经网络里有相当一部分算力，长期被浪费在“识别已经见过的局部模式”上。这部分工作本质上不需要推理，只需要查表。把它拿掉，推理反而变强。

用一个程序员熟悉的角度看：这就像发现一段核心代码里，一半时间花在反复解析同一批常量上。抽出来做成预计算表，剩下的逻辑跑得更快——而且不是因为代码变短了，是因为原来被占用的执行深度空出来了。

## 二、Jev：接口形态从根上错了

Jev 是 TypeSafe AI 第一个 System One Model。它的做法比 Engram 更激进：**直接把生成砍掉。**

不给它一段话，它不会回一段话。你给它一份 state（文本、日志、JSON 状态）加一组预定义问题，它返回类型化的决策——Noul 给 0 到 1 的概率、Choice 给选项分布和置信度、Score 给档位和概率分布。答案被约束在给定空间里，不会跑出类型，不需要解析、清洗、兜底。

代价是它彻底不能写东西。收益是速度提升 20–200 倍，成本下降 40–400 倍，输入 $0.042/百万 token，输出干脆免费，端到端 70–500 毫秒。

它背后的判断比技术更值得注意：**智能的消费者正在从人变成代码。**过去几年整个行业优化的是“怎么把话说得更好听”，但真正消费智能的其实是软件流程里的 if 分支。代码不需要文采，不需要解释，只需要一个能直接执行的判断。

于是 Agent 的质检、工单的路由、每一步的验收、上下文该压缩哪些——这些高频、低认知负载但极耗成本的环节，第一次有了匹配的形态。发布几天内社区就有人用 Qwen3.5-4B 加强后训练糊出了开源复刻版（AlexWortega/openjev），说明这件事本身没有黑魔法，新的只是接口形态和置信度设计。

---

## 三、共同点：都在做减法

这两个工作看起来毫不相干。一个在预训练阶段改架构，一个在推理阶段改接口；一个出自 DeepSeek，一个出自 OpenAI 前研究员；一个为了提效，一个为了降本。

但它们在做同一件事：**把不该由神经网络承担的部分，从神经网络里拿掉。**

Engram 拿掉的是静态查找——那件事查表就够了，不需要梯度下降学出来的泛化能力。Jev 拿掉的是文本生成——那件事对代码消费者来说是纯开销，慢且贵，还要额外写解析。

而且两者的发现方向一致得惊人：Engram 砍掉查找之后，**推理能力反而变强了**；Jev 砍掉生成之后，**判断速度提升了两个数量级**。

这不是巧合。这是同一件事的两面：智能从来不是一个可以无限放大的单一量，它由不同性质的部件组成，每个部件有各自的最优形态。硬把它们塞进一个自回归大模型里，每一部分都在为其他部分付代价。

---

## 四、三层：编译期、运行时、慢推理

把三者放到一起，得到的不是一个“更聪明的模型”，而是一套分层的东西。

```
                      请求
                        │
                        ▼
        ┌───────────────────────────────────┐
        │  L0  条件记忆（编译期）              │
        │                                    │
        │  Engram 表 / NGM / Engram Adapter  │
        │  · 静态模式、领域知识、局部依赖      │
        │  · O(1) 确定性寻址                 │
        │  · 作用：解放 early layers 的深度   │
        └───────────────┬────────────────────┘
                        ▼
        ┌───────────────────────────────────┐
        │  L1/L2  Jev（运行时，~300ms）       │
        │                                    │
        │  路由判断 · 步骤验收 · 阈值决策      │
        │  高频闭环，带校准概率                │
        └───────────────┬────────────────────┘
                        ▼
        ┌───────────────────────────────────┐
        │  L3  LLM 慢推理（运行时）            │
        │                                    │
        │  规划 · 生成 · 长链条推理            │
        │  内部已经含 L0 的记忆支撑            │
        └───────────────────────────────────┘
```

关键在于**这个分层是不对称的**：

**L0 是编译期的。**Engram 表主要在预训练或离线构造阶段形成，不能随请求实时改写。这不是缺陷，是设计约束。

**L1/L2/L3 是运行时的。**每次请求都重新决策。

这个不对称决定了整个系统的行为特征：**它的能力变更走发版流程，不走热更新。**上线后的行为是可预测的，每一版的记忆表是固定的、可复盘的，出问题能整体回滚。对一个要进生产系统的组件来说，这比“能实时学习”更值钱。

## 五、工程化的四个硬约束

想清楚约束，比想清楚架构重要。

### 约束一：记忆不是越多越好

Engram 论文提出 Sparsity Allocation 问题，揭示了一条 **U 形 scaling law**——在“神经计算（MoE）”和“静态记忆（Engram）”之间存在一个最优配比，任何一边过度膨胀都会掉。

后续研究（arXiv:2601.16531）还发现一个反直觉现象：高频 key 的 loss 初始更低，但训练后期会被低频位置反超，而哈希碰撞反而起到了隐式正则化的作用。用完美哈希消除碰撞，在严格 iso-parameter 下并不能稳定提升——瓶颈在 gate 的 credit assignment，不在索引精度。

实践含义：不要看到“加记忆能涨点”就无脑加大表。得在自己的规模上扫一遍配比，先确认 gate 学得对不对。

### 约束二：学习回路以版本为单位

Engram 表不能运行时改写，所以“慢思考的结果实时固化成快思考”这条路走不通。修正后的回路是：

```
流量 ──► Jev 路由/闭环 ──► LLM 慢推理
                              │
                              ▼
                     积累 (state, decision, 是否验证)
                              │
                              ▼
                    ─── 离线批处理（小时/天级）───
                    a) 构造/扩充 Engram 表
                    b) 训练 Engram Adapter 做域内特化
                    c) 蒸馏独立的 Jev 类小模型
                    ───────────┬──────────────
                               ▼
                           下一版模型
```

如果确实需要实时生效，现在有几条现实路径：NGM 完全不动权重、plug-and-play；Engram Adapter 把预训练记忆重新用途化为 post-hoc adapter，OOD 性能保留 99.4%–100.1%；Memory Grafting 用更强的模型离线造表，精确查找；User as Engram 把不同用户的事实写进不相交的 hash slot，实现多用户无损叠加，内存占用比 per-user LoRA 小约 33,000 倍。

选哪条取决于能不能接受动权重，以及要不要多租户隔离。

### 约束三：确定性寻址是工程上最大的甜点

Engram 的寻址是确定性的（N-gram 哈希 → 表偏移），这意味着可以在前向计算开始**之前**就从主机内存预取对应的 embedding 行。传统 MoE 做不到这一点，因为专家是动态路由的。

直接后果：Engram 表可以做得非常大，不必全驻显存。已有工作把它推进 CXL 内存池（arXiv:2603.10087，集成进 SGLang，端到端接近纯 DRAM 性能）和 SSD 层级（TF-Engram）。

这意味着 L0 这一层的容量上限比想象中高得多，而且几乎不占 GPU 预算。这是整个架构里最被低估的工程红利。

### 约束四：置信度必须有价格

Jev 输出的是概率，不是答案。生产逻辑必须写成：

```python
if p >= 0.90:
    auto()               # 高置信，直接执行
elif top1 - top2 >= 0.30:
    auto_with_flag()     # 领先明显，处理并打标待审
else:
    escalate()           # 分布接近，交 LLM 或人工
```

中间那一档是成本和质量的分水岭。而且要看**概率分布**，不是选中项——`{"billing": 0.45, "technical": 0.43}` 和 `{"billing": 0.99}` 的选中项一样，但前者该走人工。

没有这一层，模型给出的概率就只是装饰。

## 六、判断

基于以上，几个判断。

**第一，AGI 不会以单个模型的形态到来，会以分层的系统形态到来。**不是更大的大脑，是一套分工的神经系统——查表、反射、判断、推理各有各的最优形态。Engram 和 Jev 的意义不在于它们本身多强，而在于它们证明了“智能可拆”不是空想，而且拆开之后每一部分都变得更便宜、更快或更强。

**第二，护城河正在从“我有最强模型”转向“我会分层”。**Fugu 已经用一池开源模型跑出了接近前沿的成绩，DiffusionGemma 证明换生成范式的成本不到原预训练预算的 10%，Engram 证明加记忆比加计算更划算。模型正在变成可替换件，剩下的差异在工程设计。

**第三，单模型 benchmark 对分层系统正在失去意义。**Jev 干脆不发标准基准分（发布前专门写文章说榜单发布即退役），Fugu 是黑盒且它打败的是它雇来的模型。拿单体模型和分层系统比跑分，这件事本身在失效。未来值钱的是“你自己的业务上的 500 条带标注数据”——那也是唯一有意义的评测。

**第四，这条路径对中小团队反而更友好。**规模化叙事要求的是钱，分层叙事要求的是判断力——知道哪一层该用什么形态、阈值设在哪、什么算值得进训练集。这是一个工程问题，不是一个资本问题。社区用 Qwen3.5-4B 糊出 Jev 的复刻、用 Qwen3-0.6B 做训练-free 的 NGM，都是这个逻辑的注脚。

**第五，别指望一个模块通吃。**编译期和运行时的分工是硬约束，违反它就会做出四不像——把 Engram 当缓存用会丢掉它真正的价值（解放推理深度），把 Jev 当聊天模型用会丢掉它的速度优势。分层的美感恰恰来自各层不通用。

---

## 最后

把智能拆开，比把智能放大更难。放大只需要钱，拆开需要判断力。

而这可能是过去几年里，第一次出现一条不需要先融几十亿就能参与的 AGI 路径——它的入场券不是算力，是想清楚哪些事根本不该由神经网络来干。

这大概就是 2026 年这些看起来零散的工作，共同指向的那件事。
