# Jev、System One 和确定性小模型：想象空间，或者幻觉

> 当智能的消费方从人变成代码，延迟、确定性和单位成本就取代了“聪明程度”，成为第一约束。

*发布于 2026年9月29日*

---

最近 AI 圈最热闹的模型，不是一个更会聊天的模型，而是一个**几乎不说话的模型**。

9 月 15 日，TypeSafe AI 发布了 Jev，把它叫做“System One Model”。短短几天，它在 Hacker News 拿下 1893 分、496 条评论，上架 Vercel AI Gateway 24 小时内近 13% 的付费团队试过——平台历史上采用最快的一次模型发布。然后社区老哥们连夜用 Qwen 糊出了开源复刻版。热闹是挺热闹的，但这事到底有几分成色，值得拆开看看。

![三条路线都在攻击自回归的串行瓶颈：Jev、Needle、DiffusionGemma](/images/posts/jev-system-one/three-routes.svg)
*图：Jev 砍掉生成、Needle 压进端侧、DiffusionGemma 用扩散并行——三个方向，同一个瓶颈。*

---

## 一、Jev 是个什么东西

Jev 来自 TypeSafe AI，创始人 Diogo Almeida 是 InstructGPT 论文联合作者、RLHF 工作的核心贡献者之一——也就是当年让 GPT 学会说人话的那批人。他的动机说得很直白：“我们手里握着瓶中的闪电，可它却没什么用。”过去几年行业优化的是人类语言，但真正消费智能的其实是软件。

Jev 的使用方式和大模型很不一样。给它一份 `state`（一段文本、日志、工单，或者一个 JSON 状态），再给它一组提前定义好的 `questions`，它返回的不是一段回答，而是**类型化的决策**：

| 原语 | 回答什么 | 返回什么 |
|---|---|---|
| Noul | 是 / 否 | 0 到 1 的概率 |
| Choice | 选哪个 | 选项 + 全分布概率 + 置信度 |
| Score | 到什么程度 | 分数 + 档位说明 + 概率分布 |

一个请求可以混用三种原语，多个问题针对同一份 state 并行评估，加问题几乎不增加延迟。关键是：**答案被约束在你给的选项里，模型给不出选项外的值**。

官方口径的数字很唬人：比前沿 LLM 快 20–200 倍，便宜 40–400 倍，输入 $0.042/百万 token，输出免费，端到端延迟 70–500 毫秒。名字也有说法：“System One”取自卡尼曼《思考，快与慢》里的系统 1（快速直觉判断）；“Jev”取自经济学家杰文斯——杰文斯悖论说，蒸汽机效率提升后煤炭消耗反而暴增。TypeSafe 的赌注是：智能便宜到可以忽略时，被塞进软件的次数会指数级上涨。

官方给出的 Use Case 地图也很清楚：分类、路由、评分、提取、条件分支、验证、实时应用——全是软件流程里的“判断”位置。代码安排流程，Jev 负责语义判断，别的模型继续干文字生成。

```
         state（文本 / JSON / 日志）
              │
    ┌─────────┼─────────┐
    ▼         ▼         ▼
  Noul      Choice     Score
  0.87      billing    1.3
            (0.84)     (置信度 0.9)
              │
              ▼
     代码 if/else 直接消费，无需解析
```

当然，要冷静看的细节也不少：权重没公开、参数量没公布、跑在 waitlist 后面的托管 API 上；发布前官方还专门写了篇文章叫《Lies, Damned Lies, and Benchmarks》，宣布不发标准基准分——意思是没有任何公开榜单可以外推到你的业务。至于“零幻觉”，官方自己的解释是输出结构的保证：它不会凭空编一个选项 D，也不至于把数字写成一段话——但它**照样可能选错**。“不会跑出类型”和“不会判错”是两件事，宣传里这两件事有时候被捏成了一句。

## 二、Needle：另一个方向，同一件事

如果说 Jev 是“云端的快速裁判”，那 Cactus Compute 的 Needle 就是“塞进手表的快速裁判”。

Needle 2 是个 45M 参数的模型，权重加推理引擎打包成**一个 14MB 的文件**，跑起来一个会话约 28MB 内存，全程离线。它只做三件事：工具调用、设备控制、结构化提取。设计上相当激进：自研 Simple Attention Network，Hadamard MLP 替代传统 FFN，2-bit 量化；字节级语法约束保证输出的 JSON 不会格式错误；256-token 滑动窗口加 KV sinks，聊 100 轮还是 1000 轮内存都稳定在 28MB；声明几百个工具，每次只渲染最相关的 5 个；每次响应还带一个校准过的置信度，可以设阈值，低于阈值交人工——避免半夜把“调暗灯光”理解成“全部打开”。

实测数据：树莓派 5 上加载不到 1 秒，解码约 500 tokens/s；三星 A54 手机上约 350 tokens/s。基准上和 FunctionGemma 270M、LFM2.5 230M、Apple FM 互有胜负，体积是它们的 1/5 到 1/70。团队瞄准的盘子也直白：全球 210 亿台 IoT 设备，大部分是两百美元以下、没有 NPU 的硬件。

一边是 Jev 的“云端高速判断”，一边是 Needle 的“端侧离线执行”，背后是同一件事：**大多数智能消费场景不需要一篇作文，只需要一个能执行的判断**。

## 三、“带智商的高速 if-else”和高智能慢模型的差别

把两类模型摆在一起，差异主要在三个维度：

| 维度 | LLM（系统 2 倾向） | Jev / Needle 这类 |
|---|---|---|
| 响应速度 | 数秒到数十秒；开思考更长 | 70–500ms；端侧毫秒级 |
| 确定性 | 自由文本，要解析、清洗、兜底 | 类型化输出 / 语法约束，可直接分支 |
| 成本 | 输入 $0.20–10/百万 token，输出约为输入 5 倍 | $0.042/百万 token，输出免费；端侧零边际成本 |
| 出错方式 | 格式跑偏、标签幻觉、置信度不可信 | 不跑出类型，但判断仍可能错 |

延迟这件事值得单独说。LLM 的自回归解码是一个 token 一个 token 往外蹦，每个都依赖上一个——这不是工程没优化好，是原理决定的串行。而 Jev 不做自回归，一次前向并行算完所有问题；Needle 干脆把窗口和输出空间都压到极小。

慢模型的“智能”和“慢”是绑定的，这类模型的卖点就是把它们解绑：只保留判断，砍掉生成。

那为什么官方和社区的 Showcase 高度集中在游戏和 Computer Use？原因不复杂：

**这些地方 LLM 恰好做不好。**Doom 里怪物贴脸了，决策窗口是几十上百毫秒；浏览器 Agent 要决定点哪个按钮，等模型慢悠悠生成三行 JSON，用户已经走了。游戏和 Computer Use 的反馈回路紧、状态到动作的映射直接、不需要文采——正好撞在 LLM 的短板上。

**这些地方价值高。**Agent 连续跑几十上百步，每一步都要问“目标完成了没”“要不要继续”——判断的次数远大于生成的次数。LangChain 的 Jev-as-a-Judge 实验里，Jev 平均每次调用 0.44 秒、约 $0.00035，一致性还突出。

**这些地方传播度最高。**打游戏、点网页天然适合拍成 45 秒的演示视频。事实上出圈的案例也确实长这样：有人 40 秒分析完 724 条实时广告、产生 8724 次判断、花了 9 美分；有人做了个浏览器插件，刷 X 时用 Jev 以平均 380ms 判断每条帖子是不是故意引战的，命中就折叠；还有人把它接进 Claude Code 做上下文压缩，官方开发者也点了头。

Showcase 集中在游戏和 Computer Use，不代表价值只在那里。这只是**传播规律**：demo 要好看，正好好看的地方 LLM 最弱。

## 四、更“掀桌子”的想象空间

真正有意思的在 Demo 之外。

**替代传统决策系统，第一次显得可行。**很多人没意识到：写 Java 业务代码，某种程度上就是在“手写权重”——把一个业务老鸟脑子里的判断逻辑，翻译成 if-else、规则引擎、决策表。Drools 之流干了几十年这件事。现在换个思路：收集 2000 条带标注的真实案例，拿个 0.2B 的小模型把目标逻辑拟合出来，连需求文档里没说出口的 Corner case 都一并拟合了。对大量“判断密集、规则模糊、人工维护成本高”的系统来说，这条路第一次具备了工程上的想象力。

**把具身智能的泡泡吹成一点现实。**人的反应速度就在 0.2s 这个量级——看到球飞过来、脚下绊了一下、手本能地缩回，全靠系统 1。机器人的 reflex 层长期靠手写状态机，泛化能力约等于没有。一个能在相同时间尺度内做决策的模型，意味着机器人可以有一个“本能层”：小模型闭环做反射和避障，大模型在上层做规划。具身智能讲了两年故事，缺的可能恰恰是这个能以生理速度响应的决策件。

## 五、分类器、BERT，和一次迟到回归

如果你觉得“不生成、只判断”很新，那 BERT 第一个不服。

2018 年 BERT 出来后，文本分类、情感分析、意图识别、NER、句子对匹配——整个 NLP 应用层都是它的形状：预训练一次，下游拿几百条数据微调一个头，效果立竿见影。分类器模型当然有过应用潜力，而且实实在在地兑现过。后来 Transformer 赢了天下，原因也实在：GPT 式的生成式预训练加 Scaling Laws，把“一个模型干所有任务”变成了现实，微调、提示、上下文学习把任务边界抹平了；架构统一、工具链统一、人才统一，分类器那种“一个任务一个头”的玩法显得又碎又不过瘾。更微妙的是心态：判别任务被默认为“已解决”，不够前沿，资源和注意力都流向了更难的问题。

于是出现一个有点轮回意味的判断：**Transformer 负责高认知负载的问题解决，分类器模型可能回头接管高频的“填缝”工作。**

软件里绝大多数的“智能”调用，认知负载其实很低——分个类、打个标签、判个真假——但频率极高。过去给这些位置塞 LLM，是用超调查户口，慢且贵，还得配解析和兜底。Jev（Transformer 底座，RLCD 训练，约束输出）和 Needle（干脆自研微型架构）从两头印证了同一件事：判断这件事，值得一个专门的形态。

## 六、软件开发正在第三次换挡

把时间拉长，软件做“判断和决策”的方式换了三代：

**手写代码的时代。**人分析需求、画架构、写 if-else、防 Corner case。逻辑的载体是代码。

**LLM 生成代码的时代。**人生成意图，LLM 产出代码，代码继续做判断。逻辑的载体还是代码，只是作者换了。

**权重直接做决策的时代（进行中）。**判断的载体从代码变成权重——不收传单、不分单元测试，一次前向传播，答案带概率落地。

同一个问题丢给两种工程师，画风完全不同：

**Java 开发**会想：系统架构怎么设计，流程怎么 1-2-3，边界条件怎么防，事务和幂等怎么保。

**算法工程**会想：先收 2000 条 Golden Data，搞个 0.2B 模型拟合目标逻辑——包括需求文档里没写出来的那些部分。

第二种过去常被第一种同情：“拟合出来的黑盒，怎么维护？”但在判断密集型场景里，这个问题的分量在下降：有校准过的置信度、有概率分布、有兜底阈值，误报漏报的代价被显式写进业务逻辑而不是藏在代码深处。看起来，后者真有成为通解的潜质。对系统工程师来说，这是实打实的能力洗牌风险——大家刚学会 Agentic Coding，技能需求的版本号又默默 +1：写逻辑的手艺在贬值，**定义判断边界、造 Golden Data、设计评估和置信度阈值、设计升级路径**的手艺在升值。

## 七、复刻一下，再听听冷水

社区对“Jev 调子起太高”的质疑，最有力的回应不是嘴仗，是复刻。发布几天内 GitHub 和 Hugging Face 上冒出一堆 OpenJev，同名不同路：

**AlexWortega/openjev**：把 Qwen3.5-4B 当 NLI 交叉编码器重新训，提供 predict / rerank / grade 三个方法，MIT 协议，零样本就能玩 Flappy Bird 和 Doom。这是“判断这件事，通用模型加强后训练就能糊出来”的最直接证据。

**ekzhang/openjev-sglang**：不改训练，prefill-only 读选项的 logprobs，Qwen3.6-35B-A3B + SGLang + Radix Cache，一份上下文只算一次，多个问题并行复用。这是“接口层就能复刻形态”的证据。

**hr98w/jev-visual**：换成 Qwen3.5-0.8B + MLX，在 Mac 上做出能看图的视觉版——官方 Doom 演示喂的其实是结构化状态，不是图像。

想自己复现，路径基本收敛为四步：选一个小基座；把 (state, question, 选项) 构造成 NLI 式样本对；做 SFT 或轻量 RL 拟合目标判断；推理时只读选项位的 logits、约束解码、量延迟和成本。真正稀缺的从来不是架构，是那 2000 条干净的 Golden Data——你看，绕一圈又回到了算法工程师的赛道。

还有一缕值得注意的风向：Google DeepMind 的 **DiffusionGemma**。这个基于 Gemma 4（26B MoE）的实验性开源模型用文本扩散架构，每步并行处理最多 256 个 token，单卡 H100 上速度是同等自回归模型的约 4 倍，Apache 2.0 协议。官方自己泼了冷水：质量低于标准 Gemma，生产环境别用，优势主要在本地低并发场景。但方向上的信号很清楚——连“生成”这一层都开始有人撬自回归的墙了。Jev 砍掉生成、扩散模型并行生成，两条路其实在往同一个方向使劲：**并行、少串行、快判断。**

## 八、结语：想象空间和幻觉的边界

把吹的和对的分开，大概是这样一个局面：

**真实的部分**：速度和成本的数字可独立验证，“判断”作为独立模型形态的需求真实存在且被迅速采用，社区用 Qwen 就能糊出类似效果，说明技术门槛没有传说中玄乎。

**存疑的部分**：“零幻觉”被偷换过概念；没有权重、没有参数量、没有可外推的基准；Jev-as-a-Judge 这类实验官方自己都强调是早期小规模测试；0.2s 决策在机器人上到底能不能打，现在谁也给不出答案。

但无论 TypeSafe 这家公司的调子最终被打几折，有一个判断大概率成立：**当判断的成本和延迟下降一个数量级，软件里“判断”的出现次数会上升几个数量级。**这本来就是 Jev 这个名字想讲的故事——杰文斯悖论。

大家刚学会 Agentic Coding，一回头，软件工程的基本单位可能又要改了。好戏还在后头。
